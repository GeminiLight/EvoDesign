# Contributor guides

Start with [Contributing to EvoDesign](../CONTRIBUTING.md) for environment setup,
the repository map and pull request expectations.

| Guide | Use it when you need to… |
| --- | --- |
| [Engineering quality](engineering-quality.md) | Choose tests, verify the user journey, or record a model-assisted validation run |
| [Backend API](backend-api-surface.md) | Integrate with the API or change routes, authentication, schemas and streaming events |

The guides describe current behavior, with links to its executable contracts.
When changing a contract, update the code, tests and relevant guide together.
Keep operational recipes short: prerequisites, procedure, verification and
recovery. Put historical experiments and future proposals in separate documents
so contributors can distinguish current requirements from plans.
