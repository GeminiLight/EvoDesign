# 迁移前后算法核验计划

> 本文件是本轮核验的执行契约。先完成并保存计划，再启动子智能体。核验生产代码只读；不提交、不部署，不用改基准来获得通过。

## 1. 目标与判定边界

核验 Python → TypeScript → 浏览器迁移是否改变算法、默认参数、模型输入、控制流或最终产物，并为每项差异提供可复现证据。沿用三期迁移计划的模块映射、Python 语义规则及逐阶段定位方法，但不把历史“测试通过”直接当作等价结论。

算法范围包括：路由与生成决策、提示词和资源、JSON 解析及校验、样式与尺寸估算、布局压缩与连线路由、设计系统、确定性校验、质量策略、评审与修复轮次、模型参数/重试、网页编排、渲染及裁剪。持久化、账号、记忆及学习只核验是否符合原计划明确排除的边界；不要求迁移这些功能。

旧网页的单次模型简化生成器不是迁移的算法基准，删除该流程是第三期的既定目标。真实模型两次出图的不同也不能直接证明算法改变。

## 3. 差异分类与验收

| 分类 | 定义 | 对结论的影响 |
|---|---|---|
| E：已核验等价 | 指定输入域上源码检查和实际对照均一致 | 仅声明覆盖范围内等价 |
| I：主动行为改变 | A→B 的功能修复，或原迁移计划明确规定的行为调整 | 列出 before/after；不能称原始行为完全相同 |
| P：平台适配 | IO、异步、PNG 编码、Worker 传输等改变 | 需证明计算内容、决策与可见结果未被改变 |
| D：迁移偏差 | 同条件下 Python/TS 的决策、参数、控制流或结果不同 | 必须列出首个分歧和复现；阻止无差别结论 |
| U：证据不足 | 无向量、路径未执行、依赖缺失或无法复现 | 单列缺口，不能计为通过 |

严重度按用户影响划分：P0 无法运行或主要结果错误；P1 改变有效输入的语义、布局、质量判断或调用策略；P2 边界/异常路径、可见元信息或较小差异；P3 文档或证据质量问题。无需把有意排除的功能判为迁移缺陷。

严格门槛：结构、字符串、布尔、null 与缺失字段精确比较；数值沿用原迁移阈值 `1e-6`，同时报告容差命中，涉及分支选择/排序不得被容差掩盖；set 只在语义确属无序时忽略顺序；模型 messages、工具与参数逐项比较；PNG 分开比较尺寸、RGBA 和编码字节。不得删除关键字段、扩大容差、改录制回复或重录基准来消除失败。

## 5. 每个子智能体的约束和交付格式

1. 先读本计划及适用的 AGENTS.md，再按 `migration/modules.json` 及第三期新增入口建立自己的文件清单。
2. 完整检查关键路径源码，不只看迁移注释或旧报告。使用 `git show 1ac838f:<path>` 读取原始 Python；当前 Python 变化必须单列。
3. 先运行现有相关对照，再针对源码风险补充最小差分输入。允许新增专用核验脚本/测试；不改产品源码、历史 fixtures、harness 或其他智能体的报告，不安装依赖。
4. 分别记录总模块、已查模块、未查模块、向量数、跳过、失败和容差；Vitest 的测试项数不等于向量数，空选择不等于通过。
5. 每条发现包含：ID、分类、严重度、Python/TS 精确位置、触发条件、迁移前/后行为、复现命令、原始输出路径、影响与建议。没有可执行复现时明确标为静态证据。
6. 报告只写入各自 `migration/verification/VA02-generation/`、`VA03-render/`、`VA04-quality/`。重型命令日志归各自目录；避免并发写同一报告。`parity:stages` 由 R 独占，`parity:runs` 由 Q 独占，`parity:web` 和全量函数测试由主智能体独占。
7. 发现 P0/P1 或需要修改共同文件时先向主智能体报告。不得把已知历史缺陷自动改好后宣称没有差异。本轮目标是核验与可审阅的结论。

## 6. 核验矩阵

| 层 | 核验与输入 | 判定/证据 |
|---|---|---|
| 基线 | A→B Python/后端 diff，C→D 入口及配置映射 | 每项主动改变或缺口登记 |
| 静态映射 | modules.json 全量模块，web_runtime 额外映射；函数/类/常量/资源及参数默认值 | 不遗漏算法模块；未覆盖模块逐个列出 |
| 函数 | 现有全部函数向量，审阅 adapter 与比较器；新增边界 | 返回值、mutation、异常及空选择有效性 |
| 阶段 | 全部阶段样例的隔离与串联对照 | 首个分歧阶段；不得只比最终图 |
| 流水线 | Node 与 MemoryFS 的完整 cassette runs | 请求、快照、产物、终态、错误 |
| 网页 | backend web cassette 与 TS streamDiagram | 模型请求、事件顺序/payload、结果及错误 |
| HTTP/Worker | 模型 HTTP 矩阵、browser smoke cassette | 参数、默认值、重试、开关、取消与序列化 |
| 渲染 | 同 manifest 的已有 112 图像证据及必要抽样重跑 | 尺寸、像素、裁剪、字体；不以模型分数代替 |
| 独立边界 | 空/缺失/False/0、负数/半值舍入、Unicode、顺序/tie、无效 JSON、无图标/多种 icon、质量阈值、失败/重试 | 由源码风险驱动，不仅重新运行旧 fixture |

优先命令：`npm test -- --maxWorkers=1`、`npm run parity:stages`、`npm run parity:runs`、`npm run parity:runs -- --fs memory`、`npm run parity:web`、`npm run test:http`、`npm run test:worker`、`npm run typecheck`、`npm run build:browser`。按文件范围避免重复全量测试。依赖本地渲染服务使用 3001，不能改动旧 3000 服务。遇到外部依赖不可用，保留失败和独立证据，不把基础设施错误算成算法等价。

本轮默认使用本地源码、现有录制回复和可控 mock；不需要新的真实模型请求。现有真实生成产物仅辅助确认用户可见影响，不能作算法等价的决定性证据。

## 7. 执行顺序与结束条件

1. 保存本计划及基线清单。
2. 同时启动 G/R/Q 三个子智能体；主智能体独立审查可信度、网页和平台。
3. 子智能体返回报告后，主智能体复现每项 D 和关键 U，必要时向原负责人分派补证。
4. 汇总四组比较、测试及算法覆盖台账；将 I/P/D/U 全部显式列出，不能以“全绿”掩盖。
5. 源文件哈希复验，生成 `ALGORITHM_VERIFICATION_REPORT.md` 及机器可读 `findings.json`、`coverage.json`、命令日志。同步用户可见材料到聊天 `outputs/algorithm-audit/`。

完成不等于全部等价：若存在可复现偏差，本轮交付必须明确回答“哪里不同、何时触发、影响是什么、接下来改什么”。最终结论只覆盖实际核验范围。
