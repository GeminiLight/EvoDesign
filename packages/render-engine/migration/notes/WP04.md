## Adapters

- **`test/adapters/...excalidraw.converter.ts` → `_icon_to_data_url`.** Its single vector comes from a pytest case that monkeypatched the icon root to an empty tmp dir, so the call raises. The adapter installs an empty virtual icon root with WP02's `useVirtualIconRoot({})`. It restores the real file system in a microtask, because the call raises and a `result` hook would never run. Nothing is skipped.
- **`test/adapters/...excalidraw.shape_size_fitter.ts` → `_translate_related`, `_resolve_container_overlaps`.**
  - In Python, the shape arguments are the same objects as the matching `by_id` entries, so moving a shape also moves its `by_id` entry.
  - JSON fixtures lose that aliasing.
  - The adapter puts it back: a `by_id[id]` entry that is structurally equal to a shape argument with that id is replaced by the shape object itself.
  - Nothing is skipped.

## Deviations and decisions

1. **`_resolve_numeric_dimension(*values, default)`.** It is ported as `(...args)` and the **last** argument is `default`. This follows §2.3: the keyword-only parameter comes after the spread values. Internal callers pass the default last.
2. **`_resolve_element_dimensions`** returns `[width, height]`, a tuple-as-array.
3. **`_position_icon_in_node`** returns `{x, y, dim}`. Its `icon_data` parameter is unused, the same as in Python.
4. **`_read_svg_as_data_uri(svg_path)`.**
   - It takes a path string relative to `evodesign/agentic_system`, which is what WP02's `require_icon_svg_path` returns.
   - Python reads raw bytes. The port reads the file as text through `readAssetText` and re-encodes it as UTF-8. That gives the same bytes for every valid UTF-8 SVG. A file with invalid UTF-8 would differ.
   - Base64 is a small local pure-TS encoder, so there is no `node:` dependency.
5. **`_stable_payload`** falls back to `pyRepr` on any exception. Python only catches `TypeError`. `pyStableJsonDumps` with `default=str` does not raise for JSON-like inputs.
6. **`fit_shape_sizes_to_text` revert loop.**
   - It walks `revert_ids` in insertion order, while Python walks it in set-hash order.
   - Each revert writes only original values keyed by its own ids. Text and icon companions are never candidates in `revert_ids`.
   - So the order does not affect the output. The 112/112 isolated stage match confirms this.
7. **Plain objects for string-keyed dicts.** `id_map`, `by_id`, `original_dims`, `shape_to_text` and `icon_by_container` are all plain objects. Excalidraw ids are 20-hex-character strings. A semantic id that looks like an integer (`"12"`) would iterate earlier in `id_map` than in Python, but only key order would change, and the harness reports key order without failing on it.
8. **`_bbox_overlap` / `_num`** use `pyFloatParse` for `float()`, so numeric strings parse and other values raise. The error is caught exactly as in Python.

## Known risks

- **Bundled vs SVG icons.**
  - `convert` uses `icon_file()` for bundled icons. Every stage case uses bundled icons or data URLs.
  - The SVG-file path (`_icon_to_data_url` → `require_icon_svg_path`) is covered only by the raising vector and the manual check above.
  - The material-design SVG set is not installed in this checkout (`tool_services/public/icons/material-design-icons` is empty).
- **Python `TypeError` cases are not reproduced:**
  - `shape["opacity"] >= 40` when opacity is `None`
  - non-hashable `type` / `size` values

  Such inputs never occur in the fixtures.
