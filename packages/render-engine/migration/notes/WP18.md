## 关键实现说明

- **流式回调（transport_journal）**：`NativeStreamJournal` 继承 LangChain.js 的 `BaseCallbackHandler`。`handleChatModelStart`、`handleLLMNewToken`、`handleLLMEnd`、`handleLLMError` 分别转调 Python 同名方法（`on_chat_model_start` 等）。Python 的回调在模型调用内部同步执行，所以 `except` 读到 `last_output` 时它已经写好；LangChain.js 默认可能在后台执行回调，因此构造时传入 `_awaitHandler: true`，保证同样的先后顺序。`run_id` 用作 Map 的键。`authored_characters` 用码点计数（`cpLen`）。错误文本 `f"{type(e).__name__}: {e}"` 取自 `constructor.name` 和 `message`。
- **model_copy(update={"callbacks"})**：用 `_model_copy` 浅拷贝聊天模型实例并替换 `callbacks`。`model.callbacks` 是 CallbackManager 时，先 `copy()` 再 `addHandler`；否则拼成数组，与 Python 一致。拷贝保留了 cassette 模型的 session/role/params。
- **continuation**：`complete_scene_prefix` 在码点数组上工作，下标与 Python 相同，并用 WP13 的 `pyJsonRawDecode`（CPython 扫描器）。`json.loads` 用 `pyJsonLoadsExact`。`prefix_sha256` 用 `sha256Hex`（UTF-8）。`partial[len(prefix):][:1200]` 用 `cpSlice`。退避 `time.sleep` 改为 base_agent 的 `_sleep`，测试可以替换时钟。`max_attempts`、`max_continuations` 原本是 keyword-only 参数，改成位置参数。
- **UnifiedGenerator**：
  - 构造函数为 `(model, tools=null, full_domain_knowledge=true, kwargs={})`。
  - 覆盖了 `_invoke_with_retry`，所以基类 `invoke` 的 JSON 修复循环会走 `invoke_native_scene`，不经过 `_transport_call`，与 Python 相同。
  - `invoke_with_history` 的覆盖版本与 Python 一样：不进入 `_CallBudget.scope`，每次都严格解析 JSON。
  - Python 在函数内导入 `domain_knowledge_loader`，TS 改为静态导入。
- **UNIFIED_TASK_PROMPT**：由 `emit_unified_prompt.py`（同一个 scratchpad 目录）从 Python 的 f-string AST 生成：`{{`/`}}` 已经还原，`_CANVAS_VIEWPORT_LABEL` 保留为插值，最后套 `pyStrip`。sha256 为 `da52b17dd6c637fcd9e5efe96ddc26ff074d63f696e2c9d84e22502219fa2463`，与 Python 相同；请求逐字一致也证明了这一点。Python 改动后需要重新生成。
- **`str(self._last_raw_output)`**：这是 Python 对 agent 状态字典取 repr，其中包含 LangChain 消息的 repr。TS 用 `_py_str_raw_output`/`_message_repr` 复现，规则如下：
  - 字段按声明顺序输出：`content`、`additional_kwargs`、`response_metadata`、`name`、`id`；AIMessage 再输出 `tool_calls`、`invalid_tool_calls`、`usage_metadata`。
  - 用 `default_factory` 生成的字段总是输出，其余字段只在非默认值时输出。
  - 字符串按 `pyRepr` 处理。
  - **偏差**：LangChain.js 的 `createAgent` 会在模型节点返回的 AIMessage 上加 `name: 'model'`，Python 没有这个字段。repr 时跳过 AIMessage 上值为 `'model'` 的 name。这个 AIMessage 不会再发回模型，所以不影响请求。
- **整数值浮点（ISSUES WP17-1）**：`candidate_output` 和 `generation_attempts[].output` 的 deepcopy 用 `_deepcopy_with_py_floats`（来自 WP17 的 `layout/sequence_layout.ts`），这样能保留解码器打的浮点标记。修复轮的 `json.dumps(previous["output"])` 和 `generation_validation_attempts.json` 都先经过 `_with_py_floats`，输出 `64.0`。`t_orgchart_ty__unified_repair` 的修复请求因此与 Python 逐字一致。
- **workflow**：
  - `StateGraph(UnifiedWorkflowState)` 改为 WP13 的 `PydanticStateGraph`。节点为 `generate_validate`；`set_entry_point` 改为 `addEdge(START, …)`；条件边 `{repair → generate_validate, done → END}` 与 Python 相同。
  - `except (ValueError, RuntimeError)` 改为对 `py/errors` 的 `ValueError`/`RuntimeError` 做 instanceof 判断。`PyJSONDecodeError`、`StructureValidationError`、pydantic `ValidationError` 都是 ValueError，`LLMBudgetExceeded` 是 RuntimeError。
  - `raise … from exc` 改为设置 `cause`。`exc.__cause__` 读取 `cause`，`str()` 用 `message`。
- **native_defaults**：`by_id`、`nodes` 用 `Map`。键可能是 `None` 等非字符串值，用 Map 可以保持 `dict.get` 的语义。`edge[key]` 的 KeyError 与 Python 一样急切求值。
- **sidecar**：Python 的 set 只用于差集和成员判断，报告前都经过 `sorted`（`pySorted`，按码点排序），所以 JS Set 的迭代顺序不会影响结果。

## 偏差与已知风险

1. 上面提到的 AIMessage `name='model'`，只影响 `raw_llm_output` 的 repr，已经处理。
2. 修复轮如果发生在 normalize/validate 阶段之后，`previous["output"]` 是经过第一期渲染引擎（compact/rebuild/style）改写的 manifest。引擎在计算中新得到的浮点（例如 Python 的 `64.0`）没有标记，TS 的 `json.dumps` 会写成 `64`，修复请求可能与 Python 不同。录制中没有这条路径；遇到时需要在引擎源头记录浮点标记。
3. 回调设成 await 模式是有意为之。如果去掉，`last_output` 可能在 `catch` 之后才写入，续写逻辑会失效。
