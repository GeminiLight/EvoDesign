## How the runtime is verified

- `test/py/gen_python_expected.py` writes `test/py/python_expected.json` using CPython 3.11.9 from the repo venv. It carries bit-exact float hex. To regenerate: `PYTHONPATH=. .venv/bin/python packages/render-engine/test/py/gen_python_expected.py` from the repo root.
- Coverage, all matching bit for bit or text for text:
  - about 4k `repr` / `str` of floats
  - about 32k `round(x)` / `round(x, n)` calls
  - about 6k `//` / `%` pairs (float and int)
  - about 24k format specs (`.0f` through `.3f`, `.0%`, `.1%`)
  - 22k `hypot` / `dist` calls
  - `json.dumps` over 12 values × 6 option sets, including astral and BMP sort order, control characters, U+2028, NaN/inf and indent
  - `json.loads`, including error cases
  - split / strip / case / repr on 26 strings
  - sorted / min / max tie behaviour
  - sha256 / md5
  - `east_asian_width` for every code point
- The converter's recorded vectors pass through the runtime alone: `_stable_payload` (120 vectors) and `_stable_digest` (120 vectors), using `pyStableJsonDumps` and `sha256Hex`.

## Deviations and decisions

1. **int vs float (the main risk).** TS has one number type.
   - `pyJsonDumps`, `pyStr` and `pyRepr` write integral safe integers as ints (`100`) and everything else as a Python float repr.
   - `-0` is written as `-0.0`.
   - To force float text, wrap the value as `new PyFloat(x)` (`pyFloat(x)`).
   - Scanning all fixtures for string results that embed `<digit>.0`, only two functions depend on this: `spec_utils.build_assistant_content` (handled by the adapter) and `grid_router._route_memo_key` (see the hints below). The converter's hash payloads contain no floats in any of the 120 vectors.
2. **`pyDivmod`, `floorDiv` and `pyMod` with two safe-integer operands return `0`, never `-0`.** This follows Python int semantics. A Python float `-0.0 // 2.0` would give `-0.0`; only the sign of zero differs.
3. **Last-bit differences between libm and V8.** I measured V8 against CPython on macOS with 50k random inputs each:

   | Function | Last-bit mismatches |
   |---|---|
   | `sin` | about 4% |
   | `cos` | about 4% |
   | `log` | about 6% |
   | `exp` | about 10% |
   | `atan2` | about 6% |
   | `tan` | 40% |
   | `log10` | 15% |
   | `sqrt`, `pow` | 0 |

   - Each difference is at most 1 ulp, far inside the 1e-6 tolerance.
   - In scope, `sin`/`cos` appear only in `node_icons` and `log` only in `radial_concept_compactor`.
   - `hypot`/`dist` did differ in about 25% of cases with `Math.hypot`, so I ported CPython's algorithm. It now matches bit for bit. **Never use `Math.hypot`.**
4. **Set iteration order.** `pyJsonDumps(set, default=str)` and `pyRepr(set)` use insertion order, while Python uses hash order. No vector in scope serialises a set.
5. **`pyRepr` printable check** uses JS Unicode property escapes. JS has a newer Unicode version than CPython's 14.0, so a few characters assigned after 14.0 (category `Cn` in Python) would print instead of being escaped.
6. **`globAssets`** returns paths sorted by code point, because Python's glob order depends on the file system. Every Python caller either sorts the result or only counts it.
7. **`pySorted` / `pyMin` / `pyMax`** only use `<`, like CPython. Results for NaN keys can differ from timsort, because the comparator is inconsistent there.
8. **Paths in `diagram_types`.** `SYSTEM_PROMPT_DIR` and `TYPE_PATTERNS_DIR` are strings relative to `evodesign/agentic_system`, not absolute `Path` objects.

## Hints for downstream WPs

- **Imports.** Import from the specific runtime file, e.g. `../py/json.ts`, `../../py/math.ts`.
- **Python names that map to TS functions:**
  - `Mapping.get` → `pyGet`. It raises on `None` / a list, like Python, so guard with `isMapping` when the Python code did.
  - `isinstance(x, dict)` → `isDict`.
  - `min(a, b)` → `pyMinN(a, b)`, or `Math.min` only when NaN is impossible. Ties do not matter for plain numbers.
  - `len(text)` → `cpLen`.
- **WP04 (converter).** Use the runtime exactly like this, already verified against the recorded vectors:
  - `_stable_payload` = `pyStableJsonDumps`
  - `_stable_digest` = `sha256Hex(\`${ns}:${pyStableJsonDumps(v)}\`)`
  - `_stable_seed` = `int(hex[:12], 16)` → `parseInt(hex.slice(0, 12), 16)` (48 bits, exact)
  - `md5(...)[:20]` → `md5Hex(...).slice(0, 20)`
- **WP07 (`grid_router._route_memo_key`).** The result is `repr(...)` of float tuples (`682.9, 208.0`). It is only a memo key, so it can be an internal TS key such as `pyRepr` over numbers. Its parity vectors will differ on integral floats; an adapter that skips the key result ("internal cache key; float repr of integral floats is not representable") is justified. Alternatively, rebind with `test/py/raw_floats.ts` (`bindWithFloats`) and pass `PyFloat` values through `pyRepr`.
- **WP08 (`architecture_design_system`).**
  - `os.getenv("EVODESIGN_…", "1")` → `getEnv('EVODESIGN_…', '1')`
  - `unicodedata.east_asian_width(ch) in {"W","F"}` → `east_asian_width(ch)` from `py/unicodedata.ts`
- **WP02.**
  - `common/node_icons.py` reads `common/assets/material_icons.json` → `readAssetJson('common/assets/material_icons.json')`
  - `icon_assets` globs `*/*.svg` under `tool_services/public/icons/material-design-icons` → `globAssets('tool_services/public/icons/material-design-icons', '*/*.svg')`
- **Floats that must print as `x.0`.** For floats that reach a string or hash, rebind the fixture with `bindWithFloats` in an adapter. In pipeline code, wrap the value with `PyFloat` only where Python is known to hold a float.
