## 关键实现说明

- **提示词**：`prompts.ts` 由脚本从 Python AST 逐字生成。字面量部分写成 JSON 字符串，拼接（`_CANVAS_HARD_BOUNDS_LABEL`、`_RUNTIME_INPUTS_TAIL`、`_LAYOUT_CONTRACT`、`COMPACT_JSON_OUTPUT`，以及 `.strip()`）保留为代码。`LAYOUT_TASK_PROMPT`、`COMPACT_FLOW_LAYOUT_TASK_PROMPT`、`FLOW_GRID_LAYOUT_TASK_PROMPT` 的 sha256 与 Python 相同。Python 改动后需要重新生成，生成脚本见 notes 所在会话的 scratchpad：`emit_layout_prompts.py`。
- **Python 浮点的记录（只在 TS 中存在）**：JS 的 number 无法区分 `80` 和 `80.0`。Layout 会把合并后的几何用 `json.dumps` 写进 `conversation_history`，Python 在这里输出的是 `80.0`。浮点有三个来源：
  1. 模型回复中的整数值浮点（`"y": 80.0`）。由解码器记录，见 ISSUES.md 的 WP17-1。
  2. `sequence_layout_geometry` 中的 `max(120.0, …)`、`max(64.0, …)`、`x = 100 + i*gap`、lane 和 title 的计算。TS 版在计算时同时记录每个值在 Python 里是不是 float，规则是 `max`/`min` 取第一个极值，`+`/`-` 只要有一边是 float 结果就是 float，`_estimate_text_dimensions` 的宽和高按其分支判断。
  3. `expand_flow_grid` 输出的 `[float x, float y, int w, int h]`。`LayoutAgent.run` 会给网格展开得到的节点的 x、y 加标记。

  标记统一存放在 `PY_FLOAT_MARKS`（WeakMap，从对象映射到字段名集合）。几处复制都会保留标记：`_merge_layout_with_styling` 的 deepcopy 用 `_deepcopy_with_py_floats`；字段复制用 `copyField`；`expand_layout_output` 会深拷贝，之后用 `_transfer_py_floats` 把标记转移过去，`[x,y,w,h]` 按下标对应到 `x/y/w/h`。只有写入 history 的那一份经过 `_with_py_floats`，把标记字段包成 `PyFloat`，状态里的值仍是普通 number。
- **LayoutAgent**：
  - 构造函数是 `(model, tools=null, kwargs={})`。`exclude_think`（默认 false）和 `json_retry_attempts`（默认 5）先 pop 再显式传入；`strict_json_output` 用 setdefault 设为 true。
  - `run` 是 async，调用顺序与 Python 相同。
  - `FLOW_GRID_LAYOUT_TASK_PROMPT` 在 Python 中是函数内导入，TS 改为静态导入，因为没有循环依赖。
- **LayoutWorkflow**：
  - 节点为 `estimate_sizes`、`layout`；边为 `START → estimate_sizes → layout → END`（Python 用的是 `set_entry_point`）。
  - `layout_agent` 在 `super()` 之后赋值，原因与 WP15、WP16 相同。
  - 时序图分支先 merge，再生成 `participant_order`，与 Python 的顺序一致。
- **generation_stage/workflow**：
  - Python 的 keyword-only 参数按声明顺序改成位置参数，涉及 `run`、`_run_*_stage`、`_record_stage_artifacts`、`begin_pipeline_run`、`run_pipeline_stage`、`create_generator`。
  - `resolve_generation_context`、`begin_pipeline_run`、`run_pipeline_stage`、`run` 都是 async，阶段之间严格串行。
  - `PipelineGenerationRun` 是 dataclass，改成按字段顺序接收位置参数的类。
  - `raise ValueError(str(exc)) from exc` 改为设置 `cause`。
  - `_save_stage_output` 用 `node:fs`（文件头注明 server-only），`json.dump(indent=2, ensure_ascii=False)` 改为 `pyJsonDumps({indent: 2, ensureAscii: false})`。
  - Python 在 `__init__` 内导入 structure、styling、layout 子工作流，TS 改为静态导入，因为没有循环依赖。

## 偏差与已知风险

1. 整数值浮点（ISSUES WP17-1）：本 WP 只在 Layout 写入 conversation_history 时还原 `80.0`。`layout_instantiation` 里的值仍是普通 number。Python 的产物文件里是 `80.0`，TS 写出的是 `80`；parity-runs 按 JSON 结构比较产物，所以没有影响。但下游如果把这些坐标格式化成字符串，例如 f-string、`json.dumps` 进提示词、生成 ID 的哈希，就可能出现差异。届时需要读 `PY_FLOAT_MARKS`，或者在源头单独处理。
2. 整数判断无法区分 `1` 和 `1.0`：`expand_flow_grid` 要求 `type(value) is int`，`_build_size_hints_prompt` 要求 `isinstance(…, int)`。TS 用 `Number.isInteger` 判断，所以模型输出 `[1.0, 2]` 这样的网格坐标时，Python 会拒绝，TS 会接受。录制中没有出现这种情况。
3. `flow_grid` 中 Python 的 set 只用于相等和子集判断，不会被迭代，所以顺序不影响结果。
