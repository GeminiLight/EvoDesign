## 开始时的状态与唯一的根因

开始时 `parity:runs` 是 27/36。9 个迭代修复样例全部在 `run_iteration` 快照的 `$.analysis_manifest_fingerprint` 处分歧（ISSUES.md WP23-2）。这个指纹是 `sha256(json.dumps(manifest, sort_keys=True))`，Python manifest 里大量坐标是整数值浮点（`120.0`），TS 渲染引擎写成了 `120`。

处理方式：没有在对照工具里把这个字段归一化（harness/tools 不归 WP24 改）。改为让 TS 按 Python 的规则记录每个数值是 int 还是 float，做法是在容器上加旁路标记 `PY_FLOAT_MARKS`，数值本身不变。所以值级对照（第一期和第二期）在设计上不会受影响，实际复跑也全部通过。细节、修改清单和验证见 **ISSUES.md WP24-1**。

### 定位方法（§5 的补充）

harness 按值比较，看不出 `120` 和 `120.0` 的区别，所以写了一个"浮点路径"对照：

1. Python 一侧：读 `fixtures/runs/<run>/snapshots.jsonl`（原始 JSON 保留了 `120.0`），按 `test/harness/fixtures.ts decode()` 的规则解码，列出每个快照中值为整数值浮点的 JSON 路径。
2. TS 一侧：与 `tools/parity-runs.ts` 相同地回放，在 `setSnapshotSink` 里遍历实时值（与 `toPlain` 的形状相同），把被 `PY_FLOAT_MARKS` 标记的整数值列成路径集合。
3. 逐快照比较两个集合。第一个不一致的快照就是丢标记或标错的节点，再按 Python 源码找到写入那个字段的表达式。

第一期阶段样例（`fixtures/stages/*.json`，用 `pyJsonLoadsExact` 读入，保留输入里的浮点标记）和 JSON 产物文件（读回时同样用 `pyJsonLoadsExact`）都用同样的方法检查。下面附上脚本，供 WP25 复现（WP24 不能往 `tools/` 写文件）：

```python
# pyfloats.py — 运行：PYTHONPATH=<repo> .venv/bin/python pyfloats.py  → pyfloats.json
import json, glob, os
RUNS = '<repo>/packages/render-engine/fixtures/runs'
def decode(v):
    if isinstance(v, list): return [decode(x) for x in v]
    if not isinstance(v, dict): return v
    ks = list(v)
    if ks == ['__tuple__']: return [decode(x) for x in v['__tuple__']]
    if ks == ['__set__']: return {'__SET__': [decode(x) for x in v['__set__']]}
    if ks == ['__float__']: return float(v['__float__'])
    if ks == ['__dict__']: return {str(k): decode(x) for k, x in v['__dict__']}
    if len(ks) == 2 and ('__dataclass__' in v or '__model__' in v): return decode(v['fields'])
    if len(ks) == 2 and '__message__' in v: return {'type': v['__message__'], **decode(v['fields'])}
    if ks == ['__path__']: return v['__path__']
    if len(ks) == 2 and '__enum__' in v: return decode(v['value'])
    return {k: decode(x) for k, x in v.items()}
def walk(v, p, out):
    if isinstance(v, dict): [walk(x, p + '.' + k, out) for k, x in v.items()]
    elif isinstance(v, list): [walk(x, f'{p}[{i}]', out) for i, x in enumerate(v)]
    elif isinstance(v, float) and v.is_integer(): out.append(p)
res = {}
for d in sorted(glob.glob(RUNS + '/*/')):
    name = os.path.basename(d.rstrip('/'))
    if name.startswith('_'): continue
    res[name] = []
    for line in open(d + 'snapshots.jsonl'):
        out = []; walk(decode(json.loads(line)['value']), '$', out); res[name].append(out)
json.dump(res, open('pyfloats.json', 'w'))
```

```ts
// floatcheck.mts — 运行：cd packages/render-engine && npx tsx <path>/floatcheck.mts [case 子串...]
// 回放方式与 tools/parity-runs.ts 相同（CassetteSession + runRecordedPipeline + setSnapshotSink），
// sink 中对每个快照：
function walk(value: unknown, path: string, out: string[], seen: WeakSet<object>): void {
  if (value === null || typeof value !== 'object') return;
  if (value instanceof PyFloat) { if (Number.isInteger(value.value)) out.push(path); return; }
  if (seen.has(value)) return; seen.add(value);
  try {
    const custom = (value as { toFixture?: () => unknown }).toFixture;
    if (typeof custom === 'function') return walk(custom.call(value), path, out, seen);
    if (value instanceof Map) { for (const [k, v] of value) walk(v, `${path}.${String(k)}`, out, seen); return; }
    if (value instanceof Set) return;
    const m = value as { getType?: unknown; content?: unknown; lc_serializable?: unknown };
    if (typeof m.getType === 'function' && 'content' in m && m.lc_serializable !== undefined) return;
    const marks = PY_FLOAT_MARKS.get(value);
    const entries = Array.isArray(value) ? value.map((v, i) => [String(i), v] as const) : Object.entries(value);
    for (const [k, v] of entries) {
      if (v === undefined || typeof v === 'function') continue;
      const p = Array.isArray(value) ? `${path}[${k}]` : `${path}.${k}`;
      if (typeof v === 'number') { if (marks?.has(k) && Number.isInteger(v)) out.push(p); }
      else walk(v, p, out, seen);
    }
  } finally { seen.delete(value); }
}
```

## 偏差与已知风险

- **浮点标记的覆盖范围**：录制样例和阶段样例走到的写入点都已逐一核对，作为依据的是上面三项浮点路径对照（全部一致），以及对 Python 表达式类型的逐行推导。没有任何样例走到的分支（例如某些渲染引擎回退路径），如果把整数值浮点写进 manifest，**数值仍然正确**，只是 JSON 文本里 `120.0` 会变成 `120`；如果这个值被哈希（例如分析图指纹），哈希也会不同。今后修改渲染引擎时，写 manifest 数值要用 `markF/assignF/pyUpdate`，复制要用 `pyDeepcopy/pyDictCopy`，不要用 `structuredClone` 或 `{...}`。
- **`unverifiedCallers` = 13**（9 个样例）：其中 UnifiedGenerator 7 次、RouterAgent 6 次，其他调用方都核对过类名。原因是 async/流式调度丢掉了 V8 栈上的 agent 类名，harness 只能跳过"调用方类名"这一项比较。这些调用的**请求内容（消息、图片、工具、参数）仍然逐项比较且一致**，调用顺序也一致。这是 `test/harness/cassette.ts stackCallerResolver` 的限制，不是分歧。为了让栈里出现类名而重排 TS 调用结构，会偏离 Python 的写法，所以没有这样做。
- `test/harness/runs.ts Normalizer.value` 会重建对象，标记因此丢失。目前不影响 harness，它只按值比较。如果以后要逐字节比较产物，需要一个保留标记的归一化。
