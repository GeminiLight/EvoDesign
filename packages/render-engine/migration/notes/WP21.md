## 翻译要点

- **EditOp / EditApplyOutcome**：它们在 `refinement_stage/state.py`，属于 WP22，写这个 WP 时 `src/refinement_stage/state.ts` 还不存在。`apply_edits.ts` 在模块加载时用顶层 `await import('../state.ts')` 去加载（做法同 WP19 的 `report_builder`）。文件存在就用 WP22 的 `EditOp`/`EditApplyOutcome`；不存在就用本地的等价类（`py/pydantic.ts` 的 `BaseModel`，字段、默认值相同，`op`/`source` 按 Literal 校验）。`deterministic.ts` 通过 `apply_edits.ts` 导出的 `EditOp` 来构造。fixer 只读取 `op/id/payload/rationale/source` 这几个字段（结构类型 `EditOpLike`），所以向量里解码成普通对象的 EditOp 也能直接用。
- **Finding**：只按结构类型（`FindingLike`）读取 `category/element_id/location/message`，WP19 的 `Finding` 实例和向量里的字段对象都能用。
- **以 id 为键的 dict**（`_by_id`、`by_id`、`ledger`、`origin`、`reasons`、`moved`）一律用 `Map`/`Set`，原因是数字样式的 id 在普通对象里会被重新排序，而 `fix_group_frame_zorder`、`fix_node_overlap` 生成 edit 的顺序依赖插入顺序。`_by_id` 对外返回 `Map`，对照时由 adapter 转回 dict。
- **`float()`/`int()`**：每个模块有一个私有 `_float`（`pyFloatParse`，非数字/字符串/布尔就抛 `PyTypeError`，文本与 Python 相同：`float() argument must be a string or a real number, not 'NoneType'`）。这些文本会进入 `_finite_float` 的错误信息和 `handler raised ...`，已经差分核对过。`_bump_version` 用 `pyInt`（`int("3.5")` → ValueError → 2）。
- **`max(a, b)`/`min(a, b)`** 按 Python 语义（相等时取第一个；遇到 NaN 时取第一个）用本地 `_max2`/`_min2`，不用 `Math.max`。`max(scored)` 比较 tuple，用 `pyMax`。`min(distances, key=...)` 用 `pyMin`（相等时取第一个，键顺序为 left/right/top/bottom）。
- **格式化**：`{x:.0f}`/`{x:.2f}` → `pyFormatFixed`；`{x!r}` → `pyRepr`；`w={w}`（Python float）→ `floatRepr`（`0.0` 而不是 `0`）；`{_MIN_CONTRAST_RATIO}` → `4.5`；`message[:80]` 按码点切片。
- **`_semantic_edit_error`**：`manifest.get("_meta", {}).get(...)` 在 `_meta` 为 None 时会抛 `AttributeError`，本地 `_get` 复现这一点（会变成 `handler raised AttributeError: 'NoneType' object has no attribute 'get'`）。`payload.get("strokeColor") in {...}` 遇到 list/dict 时抛 `TypeError: unhashable type`，同样做了复现。
- **`handler raised {type(exc).__name__}: {exc}`**：PyException 子类的 `name` 就是类名；`KeyError` 的 message 已经是 repr。JS 原生错误会显示 JS 的错误名和文本（见已知风险）。
- **`patch_schema_defaults`**：`setdefault` 只填缺失的键（`hasOwnProperty`）。种子用 BigInt 计算 `int(digest[:16], 16) % 2_000_000_000 + 1`。
- **`fix_node_overlap`** 的 `a, b, c, d = (float(v) for v in bbox)`：本地 `_unpack4`，元素多于或少于 4 个时抛 ValueError，不可迭代时抛 TypeError，这两种都会被 `except` 吃掉，与 Python 相同。
- **`reroute_bound_arrows`**：`route_arrow_between_bboxes` 抛出 `ValueError/TypeError/KeyError`（包括 JS 原生 `TypeError`）时跳过该箭头；`NotImplementedError`（不支持的画布）照常向上抛，与 Python 一致。`arrow.pop("fixedSegments")` → `delete`。
- **keyword-only 参数**按声明顺序变成位置参数：`apply_edits(manifest, edits, allow_icons)`、`reroute_bound_arrows(manifest, canvas_library, touched_ids, tolerance)`、`_move_bound_text(elements, container, dx, dy)`。
- 返回 None 的函数（`_bump_version`、`_move_bound_text`、`_recenter_bound_text`、`patch_schema_defaults`）显式返回 `null`。

## 已知风险

- 如果 handler 里出现 JS 原生异常（比如读取 `null` 的属性），`handler raised ...` 的文本会和 Python 不同（Python 会是 `AttributeError: 'NoneType' object has no attribute ...`）。录制样例和差分核对中都没有出现这种情况。
- `_semantic_edit_error` 里 `edit.id in semantic_ids` 用 JS `Set` 的同值比较，与 Python 的 hash 等价只在 id 为字符串时相同（id 一直是字符串）。
- WP22 的 `state.ts` 出现后会被自动采用。如果它的 `EditApplyOutcome` 构造函数对 `edit` 字段做重新校验或复制，请保持 pydantic 的行为（模型实例原样保留，`revalidate_instances='never'`）。
