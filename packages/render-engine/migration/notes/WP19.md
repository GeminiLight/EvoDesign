## 翻译要点

- **Finding / Severity**：`Finding` 用 WP13 的 `py/pydantic.ts` `BaseModel`，字段与校验与 pydantic 相同（`element_id` 非字符串、`severity` 非枚举值都会抛 `ValidationError`）。`Severity` 是 `str` 枚举，TS 中 finding 直接存字符串值（`'major'`），与 `model_dump(mode="json")` 和向量一致；`Severity.MAJOR === 'major'`。`to_dict()` = `model_dump(exclude_none=True, mode="json")`：只去掉顶层为 None 的字段（已在 Python 中确认 `location` 内部的 None 不会被去掉）。
- **`float(x)` + `except (TypeError, ValueError)`**：每个模块内一个私有 `_float`（数字/布尔/字符串走 `pyFloatParse`，其他类型抛 `PyTypeError`），`except` 对应 `PyTypeError | ValueError | TypeError`。`float(elem.get("x", 0) or 0)` 的 `or 0` 走 Python 真值。
- **以元素 id 为键的 dict**（`by_id`、`arrows`、`elements`）在只做查找的地方用 `Map`，避免整数样式 id 的键序问题，也能保留非字符串 id（Python dict 允许）。`build_explicit_member_map`、`explicit_member_to_group` 返回普通对象（向量比较的是 dict）。
- **格式化**：`{x:.0f}`/`{x:.1f}` → `pyFormatFixed`（银行家舍入同 Python）；`{x!r}` → `pyRepr`；`{node_clearance:g}` 用本地 `_formatG`；`check_out_of_canvas` 消息里的 `CANVAS_MARGIN` 等是 Python float，输出为 `16.0`、`3984.0`。
- **`_segments_intersect` / Liang-Barsky** 保持原运算顺序；`a == b`（tuple）用 `pyEq`。
- **`run_all_checks` 异常文本**：`f"{type(exc).__name__}: {exc}"`。`KeyError` 的 `str(exc)` 是键的 repr，TS 里同样输出 `KeyError: 'id'`。
- **`_MembershipContext`**：冻结类，`use_explicit` 是 getter（与 dataclass property 一致）。
- **`report_builder`**：`write_report` 写文件，因此文件头标注 `// server-only` 并使用 `node:fs`/`node:path`。`json.dumps(indent=2, ensure_ascii=False)` → `pyJsonDumps`。`_utc_timestamp` 为 `YYYY-MM-DDTHH:MM:SSZ`。
- 无返回值的函数（`_add_structure_group_aliases`、`_project_arrow_bindings`）显式返回 `null`（向量期望 None）。

## 已知风险

- 检查函数里若出现 JS 原生异常（例如对 `null` 取属性），`internal_error` 消息里的异常名/文本会与 Python 不同（Python 会是 `AttributeError`/`TypeError` 及其自己的文本）。录制样例中没有出现这种情况。
- `write_report` 用 `node:path.join`，会折叠 `..`，而 `pathlib` 不会；只影响返回的路径字符串，正常输出目录不含 `..`。
- JSON 产物中整数值的浮点（如 `170.0`）在 TS 中写成 `170`——这是全期通用的表示问题，`parity:runs` 按 JSON 值比较，不受影响。
