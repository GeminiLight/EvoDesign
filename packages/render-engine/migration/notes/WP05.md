## Deviations and decisions

1. **`is_enabled`.** It reimplements `AppSettings.get_default().render_fix_zorder`:
   - If `EVODESIGN_RENDER_FIX_ZORDER` is set and non-blank (read through `getEnv`), it is parsed with `_bool_setting` rules: `1/true/yes/on` and `0/false/no/off`. Any other value raises `ValueError`.
   - Otherwise the result is `_SETTINGS_YAML_FIX_ZORDER = true`, the `render.fix_zorder` value in `evodesign/config/defaults/settings.yaml`.
   - The YAML is not parsed at runtime, and a custom settings file is not honoured. This is the same approach as WP02's `_default_icon_base_url`.
2. **Sets.**
   - `semantic_node_ids` in `compact_architecture_layout` is a `Set` iterated in insertion order; Python iterates in hash order. The order does not affect output, because each id only resizes its own shape, label and icon, and the results feed lookup maps.
   - `_titled_semantic_bases` and `_shared_edges` return `Set<string>`, and callers only test membership.
   - `group_ids`, `row_ids` and `by_id` are used only for membership.
3. **Internal dicts are `Map`.** `elem_by_eid`, `parent_of`, `children_of`, `elements_by_id`, `original_center_x/y`, `predecessor_ids` and `authored_rank` are `Map`s, so ids that look like integers keep insertion order. Helper functions take either a plain object or a `Map` (through `pyGet`/`pyValues`/`pyItems`), because the fixtures pass plain objects.
4. **`float(x)` with fallback.** `_num` and `_number` reproduce the `try float(x) except (TypeError, ValueError)` fallback: a number, bool or string goes through `pyFloatParse`, and anything else falls back to the default. In group_fitter, `float(...)` raises `PyTypeError` the way Python does.
5. **`_get_element_bounds`.** `x + w` goes through a private `_add` that raises `PyTypeError` on mixed or `None` operands, like Python. In JS, `null + 0` would silently give 0.
6. **Identity checks.** `element is shape`, `child_frame is not bg_elem` and `f is not bg_elem` use `===`. `group not in side_groups` uses `pyIn`, a deep comparison, as Python's list `in` does. `element.get("containerId") == shape_id` uses `pyEq`, so `None == None` still moves elements when the shape has no id, as in Python.
7. **`min` / `max` / `sorted`.** These go through `pyMin`, `pyMax`, `pyMinN`, `pyMaxN` and `pySorted`, which use tuple keys and the first-wins rule on ties. `round(x / 40)` uses `pyRound` (banker's rounding). `sum` uses `pySum` (left to right from 0, the same order of floating-point operations).
8. **Functions that return `None` return `null`.** These are `_fit_scope`, `_normalize_member_size`, `_move_*` and `_set_title_position`.

## Known risks

- **int vs float.** `_infer_band` uses `isInt(zIndex)`, so a Python float `zIndex` such as `3.0` is treated as an int in TS. No vector or sample has a float `zIndex`; WP03 has the same limitation.
- **Floating-point order.** `math.ceil` comes from `py/math.ts`. Every computation keeps Python's order of operations, and there are 0 tolerated diffs.
