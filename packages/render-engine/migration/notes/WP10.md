## 出图报告（`npm run render`）

- `tools/render.ts`：对每个阶段 fixture，写出 `reports/visual/<case>/ts.json`（TS 最终 manifest）和
  `python.json`（Python 最后一个快照的 `diagram_manifest`），然后调用 `tools/render_visual.py`。
- `tools/render_visual.py`：**只用 Python 渲染器**（`canvas_render.render_canvas(..., canvas_library='excalidraw',
  capture_output=True)`，`EXCALIDRAW_RENDER_URL=http://127.0.0.1:3001/renderers/excalidraw`）**逐个**渲染两份 manifest，
  再用 PIL 做像素对比：把两张图贴到同一块 max(宽)×max(高) 的透明画布上，只要有任何一个 RGBA 通道不同，就算该像素不同。
  输出 `python.png`、`ts.png`、`diff.png`（不同的像素标红）和 `results.json`。
- `index.html`：每个样例一行（样例名、图表类型、Python 图、TS 图、差异图、差异百分比与尺寸、阶段对照状态），
  有问题的排在前面，图片使用相对路径。
- 参数：`--case <子串>` 只跑部分样例（结果会合并进已有的 `results.json`）；`--skip-render` 只重新生成 json 和 html。
- 不会碰 3000 端口上的服务。

## 偏差与原因

1. **只支持 Excalidraw**：`RenderWorkflow` 遇到 `tldraw` 时直接抛 `ValueError`（按 §1，tldraw 不在本次范围内）。不移植 `_tldraw_nodes` 和对应的 `_run_*`。
2. **不用 langgraph**：Python 装了 langgraph 时用 `StateGraph`，没装时用 `_SequentialGraph`；两者都是线性链，执行顺序相同。TS 一律用 `_SequentialGraph`，`sequential` 参数保留但不起作用。
3. **WorkflowState**：pydantic 校验简化为 structure/layout 必须是 dict，以及 canvas_library 规范化；`run()` 里 `WorkflowState(**result_dict)` 的重建不需要（TS 中始终是同一个实例）。
4. 没有函数向量：`fixtures/functions` 里没有 workflow/state/stages 的向量（导出器没有追踪这三个模块），所以这三个模块只靠阶段对照覆盖，而阶段对照 112/112 全部通过。

## 已知风险 / 给 WP11 的提示

- 阶段 fixture 是用 Python 运行时的默认环境变量生成的（`EVODESIGN_RENDER_FIX_ZORDER`、`EVODESIGN_ARCH_DESIGN_SYSTEM`、`EVODESIGN_DESIGN_THEME` 等都没有设置）。如果复跑时 shell 里设置了这些变量，结果会不一样。
- WP06 指出：`compact_concept_map_layout` 的函数向量只覆盖了早退路径。但阶段对照覆盖了全部 112 个样例中的 concept/mindmap 类图，而且都一致。
- 出图像素差异只说明"同一个渲染器、同一份 manifest 渲染两次"是否稳定；manifest 是否一致由阶段对照判断（逐字段，误差 ≤ 1e-6）。
