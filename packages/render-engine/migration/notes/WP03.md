## Deviations and decisions

1. **`float(x)` is a local `_float` helper.** It sends numbers, bools and strings to `pyFloatParse` and raises `PyTypeError` on anything else (`None`, containers). This matches Python's `float()`. Python callers that catch `TypeError`/`ValueError` keep that behaviour, for example `_is_visible_arrow`'s opacity parse. `py/` was not modified.
2. **Keyword-only parameters.** These become positional, in Python declaration order, following §2.3:
   - `_edge_coverage(expected_edge_count, expected_edge_ids, rendered_arrow_count, rendered_semantic_edge_ids)`
   - `audit_*_manifest(manifest, structure_instantiation, arrow_coverage_threshold)`
3. **Sets.**
   - `detect_group_frame_ids`, `_frame_ids_from_id_map` and `_title_marked_frame_candidates` return `Set<string>`.
   - Iteration order inside these functions never affects the result. Every insertion is independent of the other candidates.
   - `deduplicate_group_titles` iterates `frame_ids` only to build a removal set, so its output does not depend on order.
   - `_edge_coverage` sorts the missing ids, as Python does.
4. **Internal dict lookups use `Map`.** These are `by_id`, `shapes_by_id`, `index_by_eid` and `id_counts`. They never escape, and `Map` avoids prototype keys.
5. **`_hex_to_rgb`.** It uses `pyInt(pair, 16)`. `pyInt` strips `_`, which Python would reject in a two-character literal, so the port rejects any `_` explicitly. Python would also accept non-ASCII Unicode digits, such as full-width ones; the port does not. Real colour strings never hit either case.
6. **`isinstance(z, int)` in `_has_explicit_zindex` uses `isInt`.** A Python float `zIndex` such as `3.0` would count as an int in TS. No vector or sample has a float `zIndex`.
7. **Formatting.**
   - `{x!r}` → `pyRepr`
   - `{:.0%}` → `pyFormatPercent`
   - `{:.2f}` → `pyFormatFixed`
   - `str(label)[:32]` → `cpSlice(pyStr(label), 0, 32)`, so it counts code points.
   - String `>` on fractional indices → `pyGt`, which compares code points.
8. **`_on_segment` and `_axis_box`** use `pyMinN`/`pyMaxN`. This keeps Python's NaN behaviour for `min`/`max`, where the first argument wins.

## Known risks

- int/float distinction: see deviation 6. It only matters for a float `zIndex`.
- Several functions read `.get` on values that might not be dicts. They go through `pyGet`, which raises `AttributeError` just as Python does on a non-mapping.

## Hints for downstream WPs

- **WP04, WP05 and WP07: return shapes.** The ports use plain arrays and objects:
  - `shape_bbox` returns `{x, y, w, h}`.
  - `get_edge_center` returns `{x, y}`.
  - `pick_sides_from_geometry` and `audit_sides` return a `[start, end]` tuple.
  - `detect_crossings` returns `[a_id, b_id, {segment_index_a, segment_index_b}][]`.
- **WP04, WP05 and WP07: `iter_concept_nodes` and `iter_shape_id_candidates` are generators.** Spread them (`[...gen]`) if you need a list.
- **WP07 (`arrow_routing`).** It can reuse the prepared-segment API, `prepare_crossing_segments` + `count_prepared_crossings`. The `_PreparedArrow` type is exported.
- **`normalization` (for WP04/WP05).**
  - It exports `LAYER_*` and `_SHAPE_TYPES`; `_SHAPE_TYPES` is a `ReadonlySet<string>`.
  - `sort_and_reindex` returns `[ordered, next_counter]` and mutates `elem.index` in place.
  - `deduplicate_group_titles` takes any iterable of frame ids, such as a `Set`.
- **`render_audit`.** `AuditReport`/`AuditIssue` are class instances with the same field names as the Python dataclasses. To serialise one, use `{...report}` or read the fields directly.
