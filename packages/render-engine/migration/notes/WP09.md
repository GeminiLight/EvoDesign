## 偏差与原因

1. **`textwrap.wrap` / `statistics.median`**：`src/py/` 没有对应 helper（属于 WP01），所以在
   `caption_placer.ts` 末尾写了私有的忠实移植 `_textwrapWrap`、`_median`。`_textwrapWrap` 按 CPython 3.11
   `TextWrapper` 默认选项实现（expand_tabs、replace_whitespace、drop_whitespace、break_long_words、
   break_on_hyphens），`wordsep_re` 逐字翻译成带 `u` 标志的 JS 正则（Python `\w` → `[\p{L}\p{N}_]`，
   `[^\d\W]` → `[\p{L}\p{Nl}\p{No}_]`），长度按码点计。向量只有 4 条英文，我另外用 6 条中文、混合、连字符、
   em-dash、制表符/换行的字符串和 Python 逐条对比，全部一致。如果以后别的模块也要用 textwrap，建议 WP01 把它挪到
   `src/py/textwrap.ts`。
2. **Python 里 `meta` 变量被覆盖（照原样移植）**：`apply_design_theme` 开头 `meta = result.setdefault("_meta", {})`，
   但在 mindmap/cycle/user_journey 的连线循环中又执行了 `meta = element.get("meta") or {}`，把外层的 `meta` 覆盖掉了。
   结果是，对这几种图，`meta["design_theme"]` 会写到**最后一条箭头的 `meta`** 上，而不是 `_meta` 上
   （向量 `design_theme/apply_design_theme.jsonl` 第 14–16 行就是这样：`$.elements[16].meta.design_theme`）。
   TS 版用 `let meta` 照原样复现，并在代码里加了注释。这看起来是 Python 的 bug，但修它必须改 Python，不在本 WP 范围内。
3. 表示方式：tuple → 数组；`by_eid`/`host_ink`/`node_ink`/`children`/`parent`/`best` 用 `Map`
   （`by_eid` 的 key 是原始的 `e.get("id")`，缺失时是 `null`，和 Python 的 `None` key 行为一致）；`_main_path` 返回 `Set`。
4. `_tree_emphasis` 遍历 Python 的 `set`（`ids`），顺序只影响返回 dict 的 key 顺序（不判失败），不影响值；TS 按节点顺序遍历。
5. 返回 `None` 的函数（`_resize`、`_move`）显式 `return null`，与其他 WP 的约定一致。

## 未覆盖函数

无，所有函数都有向量。

## 已知风险

- `_textwrapWrap` 的 Unicode 类别近似：Python 的 `str.isalnum()` 和 `\p{L}\p{N}` 在极少数码点（例如部分组合标记）上可能有差异；只影响带连字符/em-dash 的长说明文字的断行位置。
- `_main_path` 的 `walk` 是递归，`best` 缓存忽略 `seen`（与 Python 相同）；图非常深时，两边都可能栈溢出，但上限不同。

  返回深拷贝后的新 manifest（或者在未启用/不适用时原样返回输入对象）。

- 对 mindmap/cycle/user_journey，`design_theme` 元数据会出现在最后一条箭头的 `meta` 里（见偏差 2），阶段对照里看到这个属于正常情况。
