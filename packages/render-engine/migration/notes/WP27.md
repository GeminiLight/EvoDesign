# WP27 运行时 IO 抽象

## 做了什么

### 新增模块
- `src/py/fs.ts`
  - `RuntimeFS` 接口：`readText/readBytes/writeText/writeBytes/exists/mkdirp/list/remove/stat/copyFile/realpath/mkdtemp/tmpdir/homedir/cwd`。
  - `MemoryFS`：内存实现。
    - 路径语义与 Node（POSIX）一致；相对路径按 `cwd`（默认 `/workspace`）解析。
    - 错误与 Node 同形：`code/errno/syscall/path`，消息如 `ENOENT: no such file or directory, open '<path>'`。
    - `list` 按 UTF-16 码元排序。
    - `mkdtemp` 产生确定的伪路径 `<prefix>00000001`、`<prefix>00000002`…（8 位，与 Python `_RandomNameSequence` 的长度一致）。
    - `mount(dir, provider)` 只读挂载（写入报 EROFS）；`seed()` 预置文件；`misses` 记录查找过但不存在的路径；`files()` 列出内存中的全部文件。
  - 活动 FS：`getFS()` / `setFS()` / `withFS()`。默认值来自宿主平台。
  - 另有与 `node:fs` 同名同参的薄封装（`readFileSync`、`writeFileSync`、`existsSync`、`mkdirSync`、`statSync`、`copyFileSync`、`rmSync`、`readdirSync`、`realpathSync`、`mkdtempSync`、`tmpdir`、`homedir`、`cwd`），全部转发到 `getFS()`。迁移后的模块只换了 import 来源，调用处与 Python 仍能逐行对照。`readFileSync(path)` 不带编码时返回 `Uint8Array`。
- `src/py/path.ts`：照搬 Node `path.posix` 的算法，提供 `join/normalize/resolve/relative/dirname/basename/extname/isAbsolute/sep`。`resolve` 使用 `getFS().cwd()`。
- `src/py/bytes.ts`：替代 `Buffer`，提供 utf-8（保留 BOM，孤立代理项转为 U+FFFD）、latin1、base64、`concat`、`readUInt32BE`/`writeUInt32BE`。
- `src/py/zlib.ts`：基于 `pako@2.1.0`，提供 `deflate/inflate/gzip/gunzip`。
- 哈希：沿用已有的纯 TS 实现 `src/py/hash.ts`。`critic/comparison.ts` 原来用的 `node:crypto createHash`，已改为 `sha256Hex`。
- 宿主平台：
  - `src/py/platform_types.ts`：`Platform` 接口，包含 `createDefaultFS`、`repoRoot`、`assetProvider`、`createAsyncContext`、`spawn`、`renderExcalidrawPage`。
  - `src/py/platform.ts`：`getPlatform()` / `setPlatform(partial)`。
  - `src/py/platform_browser.ts`：浏览器实现。
    - 文件系统：`MemoryFS`。
    - `repoRoot`：`/evodesign`。
    - 资源：无，由 WP31 安装。
    - `AsyncContext`：单线程替身。
    - `spawn` / 渲染器：null。
  - `package.json` 新增 `imports`：`"#platform": { "browser": "./src/py/platform_browser.ts", "default": "./src/node/platform.ts" }`。tsx、vitest、tsc（Bundler 解析）走 `default`；esbuild/vite 的 browser 构建走 `browser`。
- `src/node/`（新建，Node 专用）：
  - `platform.ts`：Node 平台。`repoRoot` 由 `import.meta.url` 推出；`AsyncLocalStorage` 取自 `node:async_hooks`。
  - `fs.ts`：`NodeFS`。
  - `assets.ts`：资源的 Node provider，从 `src/py/assets.ts` 移来。
  - `spawn.ts`：`subprocess.run`，从 `canvas_render._spawn` 移来。
  - `excalidraw_page.ts`：playwright 驱动渲染页，`canvas_render._cli_render` 原样移来。

### 改动的流水线模块（只换 IO 来源，逻辑不变）
- **`node:fs` / `node:path` / `node:os` → `py/fs.ts`、`py/path.ts`**，涉及：
  - `agentic_system/{workflow,iterative_workflow,main}`
  - `canvas_environment/rendering`
  - `config/{settings,model_loader}`
  - `core/experiment`
  - `generation_stage/{workflow,unified/continuation,unified/generator,unified/transport_journal,unified/workflow}`
  - `refinement_stage/reports/refiner_report`
  - `render_engine/{service,canvas_render,shared/png_validation,shared/image_cropper}`
  - `utils/{env_loader,path_manager,io_utils}`
  - `verification_stage/{workflow,critic/comparison,critic/critic_agent,reports/report_builder}`
- **仓库根路径**：原来的 `resolve(dirname(fileURLToPath(import.meta.url)), '..','..','..','..')` 改为 `getPlatform().repoRoot`。在 Node 下两者的值相同。涉及 settings、model_loader、experiment、env_loader、path_manager。
- **`core/base_agent`**：`AsyncLocalStorage` 改为 `getPlatform().createAsyncContext()`。
- **`py/assets.ts`**：不再 import `node:*`。默认 provider 取自平台；新增 `getAssetProvider()`。
- **`canvas_render.ts`**：子进程和 playwright 渲染分别经 `getPlatform().spawn` / `renderExcalidrawPage` 调用；`Buffer` 改为 `Uint8Array`。`CompletedProcess.stdout/stderr` 和 `TimeoutExpired.output/stderr` 的类型改为 `Uint8Array`（`Buffer` 是它的子类，旧测试仍兼容）。
- **PNG**：
  - 解码：`pngjs` 改为 `fast-png@8.0.0`（在 `image_cropper._imread` 和 `io_utils` 的隔行图分支）。
  - 编码：仍用原来手写的分块代码，压缩从 `node:zlib deflateSync` 改为 pako `deflate(level 6)`。
  - 实测 pako 与 Node 25 自带 zlib 的输出字节不同（426 组样本 0 组相同）。按计划第二期图片规则（比较解码后的像素）可以接受，实际对照全绿。
  - 解码核对：对 `fixtures/runs` 下 142 个 PNG，fast-png 与 pngjs 解码出的 RGBA 逐像素一致（142/142）。
  - `pngjs` 只剩测试 harness 在用，因此保留在依赖里。

### 工具
- `tools/parity-runs.ts` 新增 `--fs memory`。每个样例使用一个全新的 `MemoryFS`：
  - 工作目录：`/tmp/evodesign-run-00000001`。
  - `AGENTIC_SYSTEM_ROOT`：用资源 provider 只读挂载，与浏览器的方式相同。
  - 仓库配置文件：预置 `configs/{settings,models}.yaml` 和 `evodesign/config/defaults/{settings,models}.yaml`。WP31 在浏览器里改为由调用方传入。
  - 数据集写入内存，产物也从内存读回比较；整个过程不写磁盘。
  - `reports/runs.json` 的每个样例增加 `fs` 和 `memory: { files, misses }` 两项。
- `tools/check-browser.ts`（`npm run check:browser`）：
  1. 用 esbuild（`platform=browser`）打包 6 个编排入口，列出 bundle 需要的全部 node 内置模块（包括第三方依赖引入的）。入口为 `agentic_system/{workflow,iterative_workflow}`、`generation_stage/workflow`、`verification_stage/workflow`、`render_engine/{workflow,service}`。
  2. 检查 `src/` 下的 `node:*` import，只允许出现在 `src/node/`、各 `__main__.ts`，以及 `agentic_system/main.ts` 的 `node:url`（命令行入口判断用）。
  3. 任何一项不满足都以 exit 1 退出。
- `test/py/runtime_io.test.ts`（7 个测试）：
  - `py/path` 与 `node:path.posix` 在 25×25 组样例上逐个比较；
  - bytes/zlib 与 `Buffer` / `node:zlib` 互通；
  - 同一脚本（34 个操作，含各种错误路径）分别在 NodeFS 和 MemoryFS 上执行，返回值、错误码、syscall、消息完全一致；
  - 挂载、确定性临时目录、`setFS`。

## 偏差与说明
- **assets.ts 的 Node provider 位置**：计划允许 `src/py/assets.ts` 的 Node provider import `node:*`。但 `assets.ts` 位于浏览器入口的依赖图内，留在原处会让 esbuild 检查失败，所以把它移到了 `src/node/assets.ts`（仍属允许的位置），`assets.ts` 本身不再 import `node:*`。
- **canvas_render 的拆分**：把 playwright / 子进程部分移进 `src/node/` 本属于 WP28 的范围；这里只做到 WP27 验收所需的程度，即平台钩子 `renderExcalidrawPage` 和 `spawn`。`PngRenderer` 接口留给 WP28。
- **`main.ts` 的 IO**：`runRecordedPipeline` 和数据集读取也已走 `RuntimeFS`，`--fs memory` 依赖这一点。只有命令行入口判断还用 `node:url` 和 `process`。
- **浏览器运行仍需后续 WP 处理的事项**：动态 `import(new URL(...))`、`AsyncContext` 并发语义、渲染脚本存在性检查。这些不影响"无 node 内置模块"的检查，已登记在 ISSUES.md WP27-2。
- **路径语义**：只支持 POSIX，不支持 Windows 路径。
