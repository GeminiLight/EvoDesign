## Styling-stage cassette replay (temporary script, not committed)

`parity:runs` cannot reach the styling node until WP23 exists, so the stage was replayed directly for every recorded run that has a `styling` graph snapshot. That covers 31 runs; the 5 one-shot runs have no styling stage.

The replay works like this:
1. Build the input `WorkflowState` from the run's `styling` snapshot with the outputs reset: `styling_specification` and `styling_instantiation` set to null, `current_stage='init'`, and `conversation_history` copied from the preceding structure snapshot. This mirrors `PipelineGeneratorWorkflow._run_styling_stage`.
2. Read `use_icons` from the recorded task prompt.
3. Run the TS `StylingWorkflow` against a `CassetteSession` that starts at the first `StylingAgent` entry.

Result: 31/31 runs are identical.
- Every LLM request matches the cassette exactly: messages, roles, model params, and callers where they could be resolved.
- This includes `t_timeline_ty__repair` (an empty answer followed by a repair turn, 2 calls) and the compact flowchart path (`flow_leave_aes__compact`, which uses `expand_styling_output`).
- The final state (all fields, including `styling_instantiation`, `styling_specification`, `conversation_history` and `current_stage`) equals the recorded snapshot.

## Translation notes

- **Prompt/contract strings**: `contracts/{base,excalidraw,tldraw}.ts` and the literal parts of `prompts.ts` (`STYLING_TASK_PROMPT`, `_ICON_INSTRUCTIONS`, `COMPACT_FLOW_STYLING_TASK_PROMPT`) were generated by a script from the Python AST literal values as JSON strings. The concatenations (`+ _RUNTIME_INPUTS_TAIL`, `.strip()`) are kept as code. Regenerate the literals if the Python text changes.
- **colorful**:
  - The catalog is read through `py/assets.ts` (`system_prompt/palette_catalog/*.md`, sorted by code point, the same as `sorted(Path.glob)` within one directory).
  - `str.splitlines()` is reimplemented with Python's separator set.
  - `_FIELD_RE` uses Python's `\w` and `\s` sets.
  - Digest truncation counts code points.
  - `PALETTES` is a plain object, safe because keys are validated snake_case, so no integer-like keys can occur.
  - `palette_hexes` returns a `Set` in insertion order. Python's set order is arbitrary, and the function has no vectors and no caller in the ported pipeline.
  - A missing key raises `KeyError` as in Python, and so does `FileNotFoundError` (a local class).
- **icon_colors**: `colorsys.rgb_to_hls` is ported line by line from CPython (3.11+ form, including the `2.0-maxc-minc` branch). `min(..., key=...)` uses `pyMin` (the first minimum wins).
- **schemas**:
  - Python sets become `Set<string>`. Every place where set order reaches a message is already sorted in Python.
  - Several `x in {...}` checks are wrapped so that an unhashable value (list or dict) raises `TypeError` instead of returning false. This keeps the exception type that `StylingAgent.run` sees the same as Python (a `TypeError` is not recorded as a validation error).
  - `re.match(...$)` also accepts a trailing `\n`, as Python does.
- **styling_agent**:
  - `run` is `async`.
  - The constructor signature is `(model, tools=null, use_icons=false, kwargs={})`. `strict_json_output` defaults to true, the same as `kwargs.setdefault`.
  - `use_icons` is assigned after `super()` because TS requires it. `BaseAgent`'s constructor never reads it.
  - `except ValueError` around `expand_styling_output` and `parse_stage_output` catches `PyJSONDecodeError` too, which is a `ValueError` subclass in both languages.
  - `styling_json.get(host, {}).get("shape")` and `(entry.get("props") or {}).get("icon")` raise `AttributeError` on non-dict values, like Python.
  - `node_ids = {n["id"] ...}` raises `TypeError` or `KeyError` like Python.
- **workflow**:
  - `set_entry_point("styling")` becomes `addEdge(START, 'styling')`.
  - `styling_agent` is assigned after `super()`. Python assigns it before `BaseWorkflow.__init__`, but the graph only reads it when a node runs.
  - The node is a closure calling `this._run_styling`.
- **state**: `pythonName = 'evodesign.agentic_system.generation_stage.styling.state.WorkflowState'`, so snapshot graph names are compared. `structure_instantiation` is a required dict field. `palette_key` defaults to `DEFAULT_PALETTE_KEY` from `../router/agent.ts` (WP15).
