## Extra end-to-end check (why it was needed)

All 27 recorded `compact_concept_map_layout` vectors come from the 112 examples. **None of those is a concept map**, so each one takes the early return. The concept-map path is covered only through the inner-function vectors, which come from pytest. To close the gap I ran two scratch scripts; nothing was added to the repo.

1. **Recorded pytest calls.** A pytest plugin wrapped `compact_concept_map_layout` while `evodesign/tests/render_engine/test_render_fidelity.py -k concept` ran (24 tests passed). It recorded 14 real input/output pairs. The TS output matches all 14 exactly under `test/harness/compare.ts`, with 0 tolerated values.
2. **300 random concept maps.** The generator covered:
   - 2 to 7 branches
   - explicit and legacy `branch_id`
   - cross links and every relation type
   - `evidence_basis` and `directionality`
   - CJK labels
   - edge orders shuffled
   - every `edge_data` label shape

   Python selected `stacked_bands` 210 times, `panel_grid` 43, `layered_lanes` 38 and `compact_radial` 9.
   - **284 of 300 match exactly.**
   - The other 16 are all caused by Python hash-seed nondeterminism (see Deviation 1). Python's own output changes with `PYTHONHASHSEED` for these cases. For each of the 16, the TS output equals the Python output under several seeds.

I also checked the functions that have no vectors directly against Python:
- `_best_branch_order` and `_best_radial_slots`: 400 random branch and interaction sets, all identical.
- `_permutations` (the port of `itertools.permutations`): emission order matches.
- `_palette_for_branch`: 11 edge cases (`None`, `branch_`, `branch_x`, `branch_-2`, `branch_1_2` and others), all identical.
- `_number`: 13 inputs (strings with `_`, whitespace, `nan`, `.5`, `5.`, `None`, bool, list, dict), all identical.

## Deviations and decisions

1. **Set iteration order in `_stacked_branch_rows` (Python is nondeterministic).**
   - Python collects `semantic_targets` (the causal/dependency targets of the anchor) into a `set`, then iterates it, appending each depth-0 target to `layers[1]`.
   - With two or more such targets, the row order depends on string hash randomisation. A different `PYTHONHASHSEED` gives a different layout. This affected 28 of the 300 random cases in Python itself.
   - The TS port iterates in edge (insertion) order, which is deterministic. It matches Python whenever there are fewer than two such targets. No recorded vector hits this case.
   - **Suggested Python fix (not applied; Python is out of scope):** use a list or `dict.fromkeys`, or sort before iterating.
   - Every other set iteration in the module is order-insensitive: `max`, `any`, counting, membership, sorted `hubs`, and independent per-node writes for `reassigned`.
2. **Representations.**
   - `_dependency_layers` returns `Map<number, string[]>` (Python `Dict[int, …]`).
   - `_branch_interactions` returns `Map<[string, string], number>` (Python tuple keys). It uses a string index for lookup and keeps the same tuple object per pair.
   - Functions that take `interactions` accept either a Map or a plain object, through `pyItems`.
3. **`elements_by_id`.**
   - Built internally as `Map<string, Dict>`, so insertion order holds for any id, including integer-like ids.
   - Helpers accept a plain object as well, because the parity fixtures pass one.
4. **Keyword-only parameters become positional, in declaration order.** This applies to:
   - `_edge_uses_containment_encoding(edge, anchor_ids, ownership)`
   - `_semantic_connector_style(edge, cross_branch, local_color)`
   - `_set_structural_edge_visibility(..., hidden_by_containment)`
5. **`_number(value, default_)`.** `default` is reserved in TS, so the parameter is named `default_`; it is still bound positionally. Behaviour:
   - numbers pass through
   - bool → 1/0
   - strings go through `pyFloatParse`
   - everything else returns the default (Python's `TypeError` path)
6. **`deepcopy` → `structuredClone`.** Aliasing inside the manifest is preserved, as with deepcopy.
7. **`math.log`** comes from `py/math.ts`. V8 and libm can differ by 1 ulp in the last bit, which is absorbed by `round(total, 3)` and the 1e-6 tolerance. No vector was tolerated.
8. **`hashlib.sha256`** → `sha256Hex` (`_stable_element_number`, `_concept_frame`). `int(hex[:12], 16)` is 48 bits and exact in a double.
9. **Python `==` on possibly-None values.** In `_move_node` and `_bound_text_elements`, `element.get("containerId") == shape.get("id")` uses `pyEq`, so `None == None` stays true, as in Python.
10. **`next(...)` without a default** in the panel-grid hub branch throws `StopIteration` from `py/errors.ts`.

## Known risks

- **Hash-seed nondeterminism** (Deviation 1). Stage parity can only fail here if a stage case is a concept map whose anchor has two or more causal/dependency targets that start at depth 0. None of the 112 stage cases is a concept map.
- **Integer-like node ids** (`"1"`, `"2"`) in the plain-object dicts (`assigned`, `sectors`, `_layer_external_preferences` result) would change key iteration order relative to Python. These dicts are only looked up, never iterated in a way that reaches the output. The one exception is `_layer_external_preferences`'s returned key order, which the harness reports and does not fail.
