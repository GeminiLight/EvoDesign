## 关键实现说明

- **pydantic 模型**（`GraphNode/GraphEdge/GraphGroup/ElementStructure`）：没有用 `py/pydantic.ts`，因为它不支持 `AliasChoices`。这里是手写的 `model_validate`，复现 pydantic v2 lax 模式对这几种字段类型的检查：`str` 不接受数字或布尔；`Optional[str]`；`List[str]`；列表元素不是 dict 时报 `Input should be a valid dictionary or instance of GraphNode`。alias 取第一个出现的（`class` 优先于 `type`），缺失时 loc 报第一个 alias。错误顺序与 pydantic 相同：字段按声明顺序，列表按下标。只有第一条错误会进入 `StructureValidationError` 的文本，它的 `loc` 和 `msg` 已用 Python 实测核对（`nodes.0.class: Field required`、`edges.0.to: Input should be a valid string` 等）。抛出的是 `py/pydantic.ts` 的 `ValidationError`，`loc` 是已用 `.` 连接的字符串。
- **`collections.Counter`** → `schemas.ts` 中的 `_Counter`：按插入顺序；`minus` 对应 `a - b`（只保留正数，按 a 的顺序）；`equals` 对应 Python 3.10+ 的 `==`（缺失计为 0）；`elements()`。为了 harness 比较提供了 `toFixture()`（空 Counter 是 `{}`）。
- tuple 作 dict 键时用 JSON 串作键。键里有 dict/list 时抛 `TypeError: unhashable type`，与 Python 相同。`restore_structure_ledger_relations` 里的 `dict(edge)` 按 Python `dict()` 的规则实现：非 dict 的边会抛同样的 `ValueError`/`TypeError`。
- `StructureLedgerOmission(message, ledger_name, missing)`：Python 的 keyword-only 参数按规则改为位置参数；`missing` 是 `[string, string, string][]`。
- `STRUCTURE_TASK_PROMPT`：两段字面量由脚本从 Python AST 逐字生成（JSON 字符串字面量），中间按 Python 的顺序拼接 `_RUNTIME_INPUTS_TAIL + _STRUCTURE_CONTRACT + COMPACT_JSON_OUTPUT`，再 `pyStrip`。Python 改动后需要重新生成。
- router 提示词：digest 文件经 `py/assets.ts` 读取（`system_prompt/*.md`）。`str.replace` 用 `split/join` 实现，避免 JS `replace` 对 `$` 的特殊处理。
- `RouterAgent.run` 中 `PALETTE_KEYS` 的导入与 Python 一样放在函数内部：用 `await import('../styling/colorful.ts')`，避免与 WP16 的循环导入（WP16 的 `styling/state.ts` 从 `router/agent.ts` 导入 `DEFAULT_PALETTE_KEY`）。
- `RouterAgent.run(text_content, user_query?)`：Python 覆盖 `run` 时改成了两个参数。为了让 TS 签名仍能赋值给 `BaseAgent.run(state)`，`user_query` 写成可选参数。Python 要求必须传入。
- `StructureAgent(model, tools=null, kwargs={})`：`kwargs.setdefault("strict_json_output", True)` 照搬。`run`、`_drop_omitted_claims` 与 Python 的控制流一致。修正轮发回的 assistant 消息是 `pyJsonDumps({specification, instantiation}, {ensureAscii:false})`，即 Python `json.dumps(..., ensure_ascii=False)` 的默认分隔符。
- `StructureWorkflow`：Python 在 `super().__init__` 之前创建 agent，TS 在 `super()` 之后创建（`_build_workflow` 在基类构造函数里运行，节点函数运行时才读取 `this.structure_agent`）。节点名 `structure`，边 `START → structure → END`。
- `WorkflowState`（structure）：`pythonName` 已设置，快照图名会被比较。`created_at` 输出 `datetime.now(UTC).isoformat()` 的格式（`...+00:00`，毫秒补成 6 位），会被归一化为 `<TIMESTAMP>`。另外导出未绑定方法形式 `WorkflowState_add_log/add_error`，供对照使用。
- `compact_decisions`：`in` 判断用 `hasOwnProperty`；边索引用 `Map`，避免 `constructor` 这类原型键。缺少 `edge["id"]`/`source`/`target` 时抛 `KeyError`，与 Python 相同。

## 偏差与已知风险

1. `_ensure_group_graph_acyclic` 中 `member_groups` 的 set 和 `adjacency` 的 set 按插入顺序迭代，Python 按哈希顺序。两种顺序只影响两条错误消息的措辞：父组冲突时报告的是哪两个父组，以及环路报告的路径。是否报错不受影响。其他 set 只用来做成员判断，或者迭代后再排序，结果与 Python 相同。
2. JS 无法区分 `1` 和 `1.0`（WP13 已记录）：模型输出 `"row": 1.0` 时，Python 的 `_is_non_negative_int` 返回 False（会报错），TS 返回 True；修正轮 `json.dumps` 中的浮点数也会写成 `1` 而不是 `1.0`。录制中没有出现这种情况。
3. pydantic `str` 在 lax 模式下还接受 bytes 和 str 的枚举子类，JSON 输入里不会出现，所以没有实现。
