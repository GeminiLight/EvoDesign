## Deviations and decisions

1. **`icon_svg` without an XML library.** Python uses `xml.etree.ElementTree`. node_icons.ts contains a small private ElementTree clone (`_etFromstring` / `_etTostring` / `_EtElement`). It reproduces:
   - expat namespace resolution
   - attribute insertion order (`set` on an existing key keeps its position)
   - `xmlns="…"` emitted first on the root
   - `register_namespace("", SVG)` (an unprefixed svg, built into `_etNamespaceMap`)
   - ` />` for empty elements
   - ElementTree's `_escape_attrib` / `_escape_cdata`
   - comments and PIs dropped, CDATA, entity and char refs, and attribute whitespace normalisation

   It is verified byte for byte on every bundled icon. Generated `ns0:` prefixes for unknown namespaces follow ET too, but no bundled icon uses them.
2. **Base64.** `icon_file` uses a local pure-TS base64 encoder over `utf8Encode` (no `btoa`/Buffer).
3. **Paths are strings.** `icon_assets_root()`, `icon_manifest_path()`, `resolve_icon_svg_path()` and `require_icon_svg_path()` return POSIX paths relative to `evodesign/agentic_system`, for example `tool_services/public/icons/material-design-icons/blue/settings.svg`. Python returns absolute `Path` objects. All file access goes through `py/assets.ts` (`assetExists`, `globAssets`, `readAssetText`, `readAssetJson`), and the files are read from their Python-side locations. The `root=` part of the error text is therefore the relative path. The parity harness only checks that the call raised, not the message.
4. **`lru_cache`.** `bundled_icons()` and `manifest_icon_names()` are memoised in module variables:
   - Each exposes `.cache_clear()`, as in Python.
   - `bundled_icons()` returns the same object on every call. Callers must not mutate it.
   - `manifest_icon_names()` does not cache failures, like Python.
   - `setAssetProvider` clears only the text cache in `assets.ts`. Call `manifest_icon_names.cache_clear()` / `bundled_icons.cache_clear()` after swapping providers.
5. **`urllib.parse.urlparse`.** A private `_urlparse` in icon_assets.ts ports CPython 3.11 `urlsplit` + `_splitparams` for the parts used: scheme, netloc and path. This covers WHATWG C0/space lstrip, removal of `\t\r\n`, the scheme-char check, the netloc split, the IPv6 bracket check, and `;params` stripping for `uses_params` schemes. `_checknetloc` (the NFKC check on non-ASCII netlocs) is not ported.
6. **`str.format`.** `format_icon_url` uses a private `_strFormat`. It supports `{name}` fields and `{{`/`}}` escapes, and raises KeyError/IndexError/ValueError the way Python does for unknown, positional and malformed fields. Conversions and format specs (`{icon!r}`, `{color:>8}`) are not supported and raise `ValueError`. Icon URL templates never use them.
7. **`AppSettings.get_default().icon_base_url`** becomes `_default_icon_base_url()` in icon_url_adder.ts (an extra, private helper):
   - If `ICON_BASE_URL` is set and not blank (read through `getEnv`), it is used.
   - Otherwise the result is the `render.icon_base_url` value from `evodesign/config/defaults/settings.yaml`, which is identical to the property's own default. The YAML file is not parsed at runtime. **If that YAML value changes, update `_SETTINGS_YAML_ICON_BASE_URL`.** A custom settings file selected with `AppSettings._override_path` is not honoured.
8. **LangChain and the CLI.**
   - `make_icon_url_adder_tool()` returns a dependency-free object with `{name, description, args_schema, func, invoke}`.
   - `IconUrlAdderInput` is a plain class.
   - `__getattr__('icon_url_adder')` builds that tool lazily. Other names raise `AttributeError`, which the vector checks.
   - `main()` (argparse + file IO) raises `NotImplementedError`.
9. **Returning `None`.** Functions with no Python return value (`sync_node_icons`, `_sync_design_cards`, the `_validate_*` functions in layout_contract, `require_icon_assets_available`) return `null`, because the vectors record `result: null`.
10. **Dict/Map handling.** `layout_contract` and `element_shape_estimator` accept both plain objects and `Map`; Map is how fixtures decode dicts with non-string keys. All access goes through `pyGet` / `pyItems` / `pyIn`. `isinstance(x, dict)` → `isMapping`. Sets of ids are `Set<string>`. `_collect_edge_contracts` returns `{edge_id: [source, target]}`.
11. **`_extract_icon_dimension`.** `isinstance(w, (int, float))` includes bool, so the port uses `isNumberOrBool`. `min(w, h)` → `pyMin([w, h])`, which keeps Python's "first wins" rule.

## Adapters

`test/adapters/evodesign.agentic_system.common.icon_assets.ts`. **Nothing is skipped.**

- **Why it is needed.** The pytest cases behind some vectors monkeypatch `icon_assets.icon_assets_root` to a tmp directory (`evodesign/tests/render_engine/test_icon_assets.py`, `test_icon_url_adder.py`). ES module exports cannot be monkeypatched.
- **What it does.** Per vector line, the adapter installs a virtual `AssetProvider` (`setAssetProvider`). Under the icon root the provider serves exactly the files that test created; every other path falls through to the real file system. The adapter then calls `manifest_icon_names.cache_clear()`, as the tests do. After each call that returns, it restores the real provider. The last function in alphabetical order never raises, so no virtual root leaks into later modules.
- **Functions and the roots they get:**

  | Function | Virtual root |
  |---|---|
  | `icon_svg_count`, `require_icon_assets_available` | line 1: manifest `{"colors": {}}`, no SVG; line 2: a manifest naming `settings` plus `blue/settings.svg` |
  | `icon_name_exists` | a manifest with `settings` and `cloud_queue` |
  | `require_icon_svg_path`, `resolve_icon_svg_path` | an empty root |

- **Exported helper.** The adapter exports `useVirtualIconRoot(files | null)`. It is available to other WPs' adapters (for example WP04's converter `_icon_to_data_url` vectors, which come from the same pytest cases).

## Known risks

- `sync_node_icons` / `_sync_design_cards` use `py/math.ts` `sin`/`cos`. V8 and libm can differ by 1 ulp there (see WP01 notes), which is far inside the 1e-6 tolerance. Every recorded vector passes.
- Icon ownership, `before_icon` / `before_text` comparisons and `id_map` lookups use `pyEq`, a deep value comparison. That matches Python's dict `==`.
- `set_node_icon` builds `index` with `pyMax` over code points and appends `"V"`. Python raises if `index` is not a string; JS would concatenate instead. No real manifest has a non-string index.
- The ElementTree clone covers what SVG icons need, not all of XML: there is no DTD entity expansion and no `xml:` attribute handling beyond prefix resolution. Bundled icons are trusted assets (the Python docstring says so), and any new icon in `material_icons.json` is covered by the same code path.

  - `require_icon_svg_path` returns a path relative to agentic_system. Read the SVG with `readAssetText(path)` from `py/assets.ts`.

- **Layout validation (WP10 workflow):** `validate_layout_instantiation(layout, structure, styling, require_complete_styling_geometry)` takes positional parameters in Python declaration order (they are keyword-only in Python).
- **Icon URL stage (WP10):** `add_icon_urls(styling, base_url?)` returns a deep copy (`structuredClone`). Without `base_url` it uses `ICON_BASE_URL` or the settings.yaml default.
