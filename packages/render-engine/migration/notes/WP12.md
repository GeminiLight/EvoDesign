## 关键决策

1. **注入点**：只替换 `evodesign.core.llm_factory.init_chat_model`。`LLMFactory.create_for_role` 包了一层，用来记下 role（generator / router / verifier / refiner）。这样主流程（`main.initialize_model`、`initialize_router_model`）、评审（`create_for_role("verifier")`）和修复（`create_for_role("refiner")`）创建模型的方式和生产环境完全一样。`evodesign/` 下的代码没有改动。
2. **调用方（caller）**：Python 在调用栈上找最近的一个 `evodesign` 对象，取它的类名。TS 没有 `self`，`cassette.ts` 默认从 V8 调用栈里取 `Class.method`（V8 显示的是接收者的类名，和 Python 的 `type(self).__name__` 一致），只认 cassette 里出现过的类名。取不到时这一项不比较，计入 `unverifiedCallers`。也可以传入自定义的 `CallerResolver`。冒烟测试中，用 `async/await` 调用时能取到调用方。
3. **模型参数**：录制时用固定的、不含机密的环境变量（`LLM_MODEL_NAME=cassette-model`、`LLM_ENDPOINT_URL=http://127.0.0.1:9/v1`），配合生产用的 `configs/models.yaml` 和 `configs/settings.yaml`。`.env` 里的每个变量都显式设为空值，所以 `.env` 不会混进来（dotenv 不会覆盖已经存在的变量）。`api_key` 一律记为 `<redacted>`。fixtures 里没有任何用户的密钥或接口地址。
4. **样例输入**：仓库里没有 `examples/configured-model` 的原始数据集（`dataset/` 不存在）。每个样例的 `content` 用该样例 Structure 里 `fact_ledger` 的 evidence 拼成；没有 evidence 时用节点标签。`query` 是固定模板。这样做是确定的，也不需要外部数据。
5. **概念图**：`examples/configured-model` 里没有概念图产物，唯一的一次尝试 `t_concept_ty` 失败了。所以手写了一个样例 `tools/run_cases/concept_ml`（由 `build_cases.py` 生成，满足 concept_map 的 branch_id / relation_type / evidence 契约），它可以完整跑通，包括径向压缩。
6. **一体化样例**：用 `4_render/diagram_manifest.json` 的元素拼出原生场景，`_meta.id_map` 从箭头的 `meta.semantic_edge_id` 补齐。有合并边（`merged_semantic_edge_ids`）的样例过不了原生契约（每条边都要有自己的箭头），所以没用 `paper_full_x2`，改用 `ecommerce_aes`。
7. **校验质量门**：`big_en_aes__refine` 修复以后客观问题依然存在，所以 `process_example` 返回 `VerificationQualityError`（success=false）。这是生产环境的正常结果，照样录制（`ACCEPTED_FAILURES`）。
8. **快照**：顶层编排 `Text2DiagramWorkflow` 不是 LangGraph，它的 7 个阶段方法算作"顶层节点"。LangGraph 节点则是把 `StateGraph.add_node` 打补丁后，在每个节点之后取快照，这样覆盖到每一个图：结构/样式/布局阶段图、一体化图、校验图、迭代修复图，以及渲染引擎自己的图。TS 侧的 `test/harness/runs.ts instrumentSnapshots()` 用同样的方式给 LangGraph.js 的 `StateGraph.prototype.addNode` 和 TS 的 `Text2DiagramWorkflow` 原型方法打补丁，产品代码不需要为对照加任何钩子。
9. **CassetteMismatch**：Python 侧是 `BaseException`，这样评审/修复里的 `except Exception` 重试循环吞不掉它。TS 没有这种区分，所以第一次不一致会同时记录在 session 上，`parity-runs` 从 session 读取，不怕异常被产品代码吞掉。
10. **合成器出错**：抛 `SynthesisError(BaseException)`，让录制直接失败，不会伪装成模型错误被重试。

## 函数向量（第二期）

- `export_fixtures.py --phase2`：对每个录制样例，在子进程里带 `--trace` 用 cassette 回放。要求回放结果和录制完全相同，否则说明追踪改变了行为，这时不写任何向量。每个样例每个函数最多保留 20 条（前 10 次调用加抽样），合并后每个函数上限 120 条。然后在同一个 tracer 下跑 `pytest evodesign/tests/{generation,verification,refinement,core,config,utils,common}`，每个函数再追加最多 60 条；测试有失败就拒绝写出。
- 只重写第二期模块各自的目录，第一期目录不动。`_summary.json` 和 `_signatures.json` 是合并，第一期的键保留原样。
- 新增编码（Python `encode()` 和 TS `decode()` 两边同步）：`__message__`（langchain 消息，只保留 content/name/tool_calls/tool_call_id，转成 `{type, ...}`）、`__path__`、`__enum__`。`str` 枚举本来就当字符串处理。pydantic 模型继续用 `__model__`。
- 追踪器的编码现在会捕获**所有**异常（以前只捕获 `Unserializable`/`RecursionError`），因为一些对象的 `model_dump()` 会抛错。追踪必须对行为无影响。
- 带 `self` 的方法：如果 `self` 是 agent/workflow 这类不可编码的对象，就不产生向量。如果 `self` 是 pydantic 状态，向量的 `args[0]` 是状态的字段，TS 侧需要 adapter。
- 参数里有路径的向量（例如读写文件的函数）带着录制时的临时路径，TS 重放时这些路径已经不存在，这类函数要在 adapter 里跳过并写明原因。

结果：18532 条向量（样例回放 16858 条，pytest 1674 条，805 个测试全部通过），覆盖 96 个模块中的 70 个、611 个函数中的 388 个；36 次带追踪的回放全部与录制相同。没有向量的模块列在 `PHASE2_PLAN.md` 附录 F。

## 给下游的提示

- **createAgent 的 systemPrompt（WP13/WP15）**：LangChain.js 的 `createAgent({systemPrompt: "..."})` 会把字符串变成 `[{type:"text", text}]` 的 content parts，而 Python 的 `create_agent` 发出的是字符串，cassette 会报 `$.request.messages[0].content` 不一致。应该传 `systemPrompt: new SystemMessage(text)`（冒烟测试第 5 项已验证与 Python 完全一致）。另外，createAgent 在没有工具时会绑定 `tools: []`；空工具列表两边都按"未绑定"处理（规则写在 `llm_cassette.py` 和 `cassette.ts` 里）。
- **LangGraph.js 的调用选项**：`control`、`executionInfo`、`promptIndex` 等运行时簿记字段由 `cassette.ts` 过滤，不算请求内容。如果出现新的 JS 专有选项，就加进 `RUNNABLE_CONFIG_KEYS`。用 `CASSETTE_DEBUG_OPTIONS=1` 可以打印所有调用选项。
- **模型参数**：TS 的 `LLMFactory` 必须用 Python `init_chat_model` 的参数名（`model`、`model_provider`、`temperature`、`timeout`、`max_retries`、`streaming`、`use_responses_api`、`default_headers`、`base_url`、`api_key`、`max_tokens`）调用 `chatModelFactory(params, role)`，这些参数逐项比较。
- **调用顺序**：cassette 按全局序号比较。不要把串行调用改成并行（PHASE2_PLAN §2 规则 6）。
- **一体化流式**：Python 替身模型只实现了 `_generate`（不流式），所以 `transport_attempts.json` 里每次的 `text_chunks` 都是 1，中断时是 0 或 1。TS 回放模型同样不流式：中断前通过 `handleLLMNewToken` 发出一次部分文本，然后抛出 `ConnectionError`。
- **快照的 graph 名**：Python 记录的是 `module.Class`（状态 schema 的 Python 全名）。TS 的 schema 可以带一个 `pythonName` 字段，这时 graph 名也会比较；不带时只比较 scope 和 node 名。
- **`raw_llm_output.txt`（一体化）**：内容是 Python `str(dict)` 的 repr，里面有 `HumanMessage(...)`。UUID 已经归一化，但 repr 格式本身 TS 必须原样复现（WP18）。

## 已知风险

- 合成的回复全部来自真实模型以前的产物，所以只覆盖"格式正确"加上 8 种注入故障。真实模型的其他怪异输出（比如 `<think>` 块、多段 JSON）不在录制范围内，需要的话以后可以加故障种类。
- 出图依赖 3001 端口的渲染服务和本机 chromium r1208。换机器或换浏览器版本后，PNG 可能出现像素差异，cassette 里的图片 part 和 PNG 产物会先报出来。
- 一体化场景是"渲染后的 manifest 再喂回去"，比真实模型的原生输出规整得多（每个元素都带全了字段）。`native_defaults` 的补全分支只覆盖到一部分，可以靠函数向量（pytest）补充。
