## 翻译要点与偏差

- **state**：`DimensionCritique`、`Critique`、`VerifierState` 基于 `py/pydantic.ts` `BaseModel`。`ge=0.0, le=10.0` 的 float、`List[str]`（不把数字转成字符串，与 pydantic v2 一致）、`str`、嵌套模型、`List[Finding]` 都用显式校验函数，触发条件与 pydantic 相同（错误文本只保证第一行格式）。`has_errors` 等 property 是原型上的 getter，不是自有字段，快照/`model_dump` 不包含它们（与 pydantic 相同）。`add_log`/`add_error` 返回 `null`；另导出 `VerifierState_add_log`/`VerifierState_add_error` 供对照用。`pythonName` 与 Python 的 `module.Class` 相同，快照的图名一致。
- **critic_agent**：
  - **`VerifierCriticAgent(model=None)` 的拆分**：Python 在构造函数里调用 `LLMFactory.create_for_role("verifier")`，TS 中这是 async，构造函数不能 await。所以 `model is None` 路径放在 `static async create(model, max_retries, retry_delay_seconds, max_image_edge)`（参数与顺序相同；先 `require_model_capabilities("verifier", {"vision"})` 再建模型）。`new VerifierCriticAgent(model, ...)` 必须传模型，传 `null` 会抛 `TypeError` 提示改用 `create`。`critique()` 是 async。
  - 重试循环：`charge_llm_run_budget()` 在 try 之外；`_is_permanent_http_error` 直接中断；只有"没拿到回答"的失败才 `await _sleep(delay)` 并加倍（`_sleep` 来自 base_agent，测试可用 `_set_clock` 替换）。`json.JSONDecodeError` 同时识别 `py/json_decoder.ts` 的 `PyJSONDecodeError` 与 `py/errors.ts` 的 `JSONDecodeError`。
  - `call_metrics.duration_ms` 用 `performance.now()`（录制时归一化为 0）；`usage` = `response.usage_metadata or {}`。
  - `review_image_edge_limit`：`Image.open(path).size` 改为读取 PNG 的 IHDR（渲染器只产出 PNG；非 PNG 抛错，对应 PIL 的 `UnidentifiedImageError`）。`float(e["x"])` 等的 `KeyError/TypeError/ValueError`、除以 0 的 `ZeroDivisionError` 都显式抛出并在同一个 except 中返回 `None`。`e.get("opacity", 100) > 0` 对非数字抛 `TypeError`（在 try 之外，与 Python 相同）。
- **prompts / comparison**：`VERIFIER_CRITIC_SYSTEM_PROMPT`、`COMPARISON_PROMPT` 由脚本从 Python 的字面值生成（JSON 字符串），Python 文本改动时需要重新生成。截断 `[:12000]` 按码点。`compare_rendered_diagrams(original_path, candidate_path, source_text, model=null)` 是 async；`model` 为空时 `(await VerifierCriticAgent.create()).model`，时机与 Python 相同（在图片编码之后）。sha256 用 `node:crypto`（文件头标注 server-only）。
- **workflow**：
  - `StateGraph(VerifierState)` → `common/base_workflow.ts` 的 `PydanticStateGraph`（节点和条件边的 path 函数收到重新校验成 `VerifierState` 的实例，与 Python LangGraph 对 pydantic schema 的行为一致）。节点名、边、条件边与 Python 完全相同。
  - `_node_run_subjective_critic` 与 `VerifierWorkflow.run` 是 async，其余三个节点是同步的。`run(manifest_path, image_path, canvas_library, structure_path, layout_path, source_text, design_constraints, output_dir, skip_critic, skip_checks, emit_markdown)`：Python 的 keyword-only 参数按声明顺序变为位置参数。
  - `Path` 语义：`parts`、`with_name`、`parent` 用本地小函数按 pathlib（POSIX）规则实现；`Path.exists()` → `existsSync`。
  - `write_report` 通过模块级对象 `_report_writer.write_report` 调用：Python 测试会 monkeypatch 本模块的 `write_report`，TS 的 import 绑定是只读的，所以留了这个替换点（行为不变）。
  - `except (KeyError, FileNotFoundError, ValueError)`：`FileNotFoundError` 按 `name === 'FileNotFoundError'` 或 `code === 'ENOENT'` 识别。`str(exc)`：`KeyError` 输出 repr，其他输出 message。
  - `_load_json` 用 `pyJsonLoadsExact`；Node 的 fs 错误（带 `code`）视为 `OSError`。
- **__main__**：`argparse` 换成只支持这些选项的小解析器（`--opt value`、`--opt=value`、唯一前缀缩写、`-h/--help`、`choices`、必填检查；错误时向 stderr 打印 usage 和 `error:` 行并抛 `SystemExit(2)`）。帮助文本是简化版（不逐字复刻 argparse 的排版）。`main(argv)` 是 async 并返回退出码；文件作为进程入口运行时等价于 `sys.exit(main())`。`Path.resolve()` 按非严格模式实现（解析已存在前缀的符号链接）。`logging.basicConfig` 无对应（TS 日志为空实现）。导入时 `ensure_env_loaded()` 包在 try 中，与 Python 相同。

- JSON 里整数值的浮点（`7.0`）在 TS 中是 `7`——全期通用的表示问题，按值比较不受影响。
